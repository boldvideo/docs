The `ai` namespace is how your app talks to Bold's AI. Chat, search, and recommendations stream by default (see [Streaming](/sdk/streaming)) and accept `stream: false` for plain JSON. Conversation history methods return JSON.

## `ai.chat(options)`

Library-wide Q&A, or scoped to one video by passing `videoId`.

```typescript
// Streaming (default)
const stream = await bold.ai.chat({ prompt: 'How do I price my SaaS?' });
for await (const event of stream) {
  if (event.type === 'text_delta') process.stdout.write(event.delta);
  if (event.type === 'sources') console.log('Sources:', event.sources);
}

// Non-streaming
const response = await bold.ai.chat({
  prompt: 'What are the best closing techniques?',
  stream: false
});
console.log(response.content);
```

**Scoped to one video** (uses only that video's transcript as context):

```typescript
const stream = await bold.ai.chat({
  videoId: 'video-id',
  prompt: 'What is discussed at the 5 minute mark?',
  currentTime: 300   // optional playback position
});
```

**Continue a conversation:**

```typescript
const stream = await bold.ai.chat({
  prompt: 'Tell me more about that',
  conversationId: 'conv-id'   // from message_start / message_complete events
});
```

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `prompt` | `string` | - | The question (required) |
| `stream` | `boolean` | `true` | SSE stream vs JSON |
| `videoId` | `string` | - | Scope to a single video |
| `currentTime` | `number` | - | Playback position (with `videoId`) |
| `conversationId` | `string` | - | Continue an existing conversation |
| `collectionId` | `string` | - | Restrict context to a collection |
| `tags` | `string[]` | - | Restrict context by tags |
| `images` | `ImageInput[]` | - | Attach images (e.g. homework review): `File`, `Blob`, or base64 |
| `signal` | `AbortSignal` | - | Cancel the request and response body |

<Callout title="Plan availability">
  Library-wide chat (no `videoId`) is the AI Coach, available on Growth and Enterprise plans. Video-scoped chat works on every plan.
</Callout>

## Stopping an answer

From `@boldvideo/bold-js` 3.3.0, pass `signal` to `chat`, `ask`, `coach`, or `search` to stop a request, in streaming or JSON mode.

```typescript
import { createClient } from '@boldvideo/bold-js';

// Server only. Keep your API key out of browser code.
const bold = createClient(process.env.BOLD_API_KEY!);
const controller = new AbortController();
// Call controller.abort() from your cancellation handler.

try {
  const stream = await bold.ai.chat({
    prompt: 'Explain pricing',
    signal: controller.signal
  });
  for await (const event of stream) {
    if (event.type === 'text_delta') console.log(event.delta);
  }
} catch (error) {
  if (!(error instanceof DOMException && error.name === 'AbortError')) throw error;
}
```

`controller.abort()` rejects pending requests or reads with the platform's `AbortError`, not `AIAPIError`. Catch around both the call and the loop, as above.

Leaving the `for await` loop with `break` (or returning after an event) also cancels the response body, without throwing. Use a signal to cancel before iteration starts or while a read is pending. On a server, you can pass the incoming request's `signal` to stop the upstream request when it aborts.

## `ai.search(options)`

Semantic search with a short AI-written summary of the results.

```typescript
const stream = await bold.ai.search({ prompt: 'pricing strategies', limit: 10 });
for await (const event of stream) {
  if (event.type === 'sources') console.log(`Found ${event.sources.length} clips`);
  if (event.type === 'text_delta') process.stdout.write(event.delta);
}
```

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `prompt` | `string` | - | Search query (required) |
| `stream` | `boolean` | `true` | SSE stream vs JSON |
| `limit` | `number` | - | Max results |
| `collectionId` / `tags` / `videoId` | - | - | Scope the search |
| `context` | `AIContextMessage[]` | - | Previous turns, for follow-up queries |
| `signal` | `AbortSignal` | - | Cancel the request and response body |

## `ai.recommendations(options)`

Topic-based recommendations, ideal for learning paths and "what should I watch next."

```typescript
const stream = await bold.ai.recommendations({
  topics: ['contract law', 'ethics', 'client management']
});

for await (const event of stream) {
  if (event.type === 'recommendations') {
    for (const rec of event.recommendations) {
      console.log(rec.topic, rec.videos.map(v => v.title));
    }
  }
  if (event.type === 'text_delta') process.stdout.write(event.delta); // AI guidance
}
```

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `topics` | `string[]` | - | Topics to cover (required) |
| `limit` | `number` | `5` | Max videos per topic (max 20) |
| `includeGuidance` | `boolean` | `true` | Narrative learning-path text |
| `collectionId` / `tags` | - | - | Scope the pool |
| `context` | `AIContextMessage[]` | - | Previous turns |
| `stream` | `boolean` | `true` | SSE stream vs JSON |

## `ai.getConversation(id)`

```typescript
const conversation = await bold.ai.getConversation('conv-id');
for (const message of conversation.messages) {
  console.log(`${message.role}: ${message.content}`);
}
```

## `ai.listConversations(options)`

Build a viewer's history list with their library and video conversations, newest first, within your credential's visibility. Available from `@boldvideo/bold-js` 3.3.0.

Call this on your server. Derive `viewer` from your authenticated session, not a request parameter, and keep the API key out of browser code. This Next.js route uses your app's `auth()` helper; the session's user ID must be the viewer's external ID in Bold (or their Bold viewer UUID).

```typescript title="app/api/conversations/route.ts"
import { createClient } from '@boldvideo/bold-js';
import { auth } from '@/auth'; // Your app's server-side session helper.

const bold = createClient(process.env.BOLD_API_KEY!);

export async function GET() {
  const session = await auth();
  if (!session?.user?.id) {
    return new Response('Unauthorized', { status: 401 });
  }

  const viewer = session.user.id;
  const page = await bold.ai.listConversations({ viewer, limit: 20, offset: 0 });
  return Response.json(page);
}
```

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `viewer` | `string` | required | Viewer UUID or external ID |
| `limit` | `number` | `20` | Page size; the server clamps it to 1–100 |
| `offset` | `number` | `0` | Number of conversations to skip; minimum 0 |

Returns `ConversationList`: `{ conversations: ConversationSummary[], pagination: { limit, offset, hasMore } }`. Each summary has these fields, without the message history:

| Field | Type | Description |
|-------|------|-------------|
| `conversationId` | `string` | ID for `ai.getConversation` or a follow-up chat |
| `scope` | `'library' \| 'video' \| null` | Conversation scope |
| `title`, `preview` | `string \| null` | Text for the history list |
| `status` | `string` | Conversation status |
| `messageCount` | `number` | Number of messages |
| `video` | `ConversationVideo \| null` | Only populated for video-scoped conversations |
| `createdAt`, `updatedAt` | `string` | Creation and update timestamps |
| `channel` | `'portal' \| 'embed' \| 'api' \| 'mcp' \| 'unknown'` | Where the conversation came from |
| `client` | `string \| null` | Client metadata |

`ConversationVideo` has `id` and `title` strings, plus nullable `thumbnailUrl` and `url` strings. Response keys are camelCase; null values and the server's pagination values are preserved.

To fetch the next page, add this inside `GET`, before `return Response.json(page)`. Keep the same session-derived `viewer` and use the returned pagination values:

```typescript
if (page.pagination.hasMore) {
  const nextPage = await bold.ai.listConversations({
    viewer,
    limit: page.pagination.limit,
    offset: page.pagination.offset + page.pagination.limit
  });
  console.log(nextPage.conversations);
}
```

HTTP failures throw `AIAPIError`, with `status` and `code`:

| Status | Code | Meaning |
|--------|------|---------|
| `400` | `viewer_required` | Supply a viewer |
| `404` | `viewer_not_found` | The viewer was not found |
| `403` | `feature_disabled` | AI is disabled |
| `403` | `verified_ai_route_unsupported` | Verified AI access keys cannot use this route |

## Multi-turn without conversations

Search and recommendations accept a `context` array instead of a conversation ID:

```typescript
const first = await bold.ai.search({ prompt: 'How do indie designers find clients?', stream: false });
const followUp = await bold.ai.search({
  prompt: 'What about cold outreach specifically?',
  context: first.context,
  stream: false
});
```

## Deprecated aliases

`ai.ask()`, `ai.coach()` → use `ai.chat()`. `ai.recommend()` → use `ai.recommendations()`. The old names still work but will be removed in v2.
